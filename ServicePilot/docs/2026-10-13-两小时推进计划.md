## 四、C-00 和 C-01 怎样验收

### C-00：代码改坏能回到哪里

1. 明确产品目录、保留航空参照与依赖范围，不把上级整个桌面或两个仓库盲目全部纳入版本控制。
2. 现有入口依赖下载仓库，必须同时保存实际需要的航空定义或记录其可恢复来源；只提交 ServicePilot 的入口不算完整基线。
3. 保存已验证的固定航空证据和启动方式，记录当前解释器与依赖版本。不要求为了保存版本重复运行整套航空问答。
4. 建立本地可回退提交与功能分支，记录提交标识和分支名；不发布远端，不覆盖已有文件，不执行破坏性的 reset。
5. 检查待提交文件，排除密钥、环境变量文件、.venv、缓存、临时截图及下载归档；文档中的示例不能出现真实密钥。

### C-01 / C02：首次订单查询真正跑通

1. query_order 的输入是订单号，实际规范化和校验由工具完成；返回结构化事实与状态。
2. 模拟记录与 PRD 一致，不能用航空座位资料代替订单数据；修改集中于业务配置与工具，不重写 SDK。
3. 从新会话输入“我的订单 A1001 到哪了？”，实际通过模型与 Agent 路由调用 query_order。
4. 事件记录证明工具参数是 A1001、状态是 ok、返回的是该订单；答复包含与记录一致的状态和物流信息，不编送达时间。
5. 留下启动命令、版本、实际答复、路由及工具证据。仅直接调用 Python 函数成功，不足以宣布完整 Agent 闭环通过。

## 五、今天理解哪些内容

把上一节的架构知识接到新功能：

- 模拟订单 JSON 是业务事实；聊天历史只是用户之前说了什么。
- query_order 是执行查询的函数；Order Agent 是使用工具的工作配置。
- Triage 的转交由模型提出，Runner 执行；工具结果还要交回模型组织答复。
- 版本基线让我们保留航空参照，在个人业务分支上改造，并且能追踪改动。

开发每次解释关联“当前目标、改哪个文件、为什么改、怎样算成功”，不先讲完整 Python 课程。
