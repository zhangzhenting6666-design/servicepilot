# ServicePilot 完整项目体系与运行架构

更新：2026-10-14。依据当前业务代码、README 和交付记录，描述**已实现的本机模拟电商售后系统**。公网部署、架构展示栏目和模拟工单分别标注为规划，不将整张图当成完整电商交易平台。

## 一句话读懂

**用户在聊天页面提问，Python 会话模块保留历史，Runner 根据当前 Agent 的配置请求 DeepSeek，执行角色交接或本地查询工具，再把依据模拟事实生成的答复与实际事件返回页面。**

模型负责理解问题、选择动作和组织语言；SDK/Runner 负责执行；Python 工具与本地 JSON 提供业务事实。三个业务 Agent 共用同一 DeepSeek 模型配置。

## 图中文字与布局

采用原图的纵向主线和右侧支撑栏：主线从界面经过会话、Agent、工具和数据，到答复返回；右侧解释模型、环境、事件和业务边界。底部展示已有验证，规划用独立虚线卡片表示。图是逻辑职责视图，多层位于同一本机 Python 应用中，不代表独立部署了多个微服务。

| 层次 | 图片主要文字 | 具体职责与代码 |
| --- | --- | --- |
| 01 用户界面 | Streamlit 聊天页面；提问、答复、新会话、实际执行事件 | `app.py` 接收输入并显示后台结果；正常模式无故障开关，页面不补造业务事实 |
| 02 应用与会话 | 历史消息 + 当前 Agent；缺信息追问、补充接续、新会话重建 | `web_runtime.py` 管理页面隔离与请求归属，`session.py` 中的 `OrderSession` 组织输入历史；该类名称保留 Order，但实际已组织订单和政策两类业务 |
| 03 编排与执行 | OpenAI Agents SDK / Runner；请求模型，执行交接或工具，按需继续 | `Runner.run` 传入当前 Agent、历史与本轮问题，执行模型输出的动作，直到最终输出或运行失败；`agent_config.py` 配置三个角色 |
| 业务角色 | Triage Agent：识别请求并分流；FAQ Agent：查询退货政策；Order Agent：追问编号、查询订单 | Triage 可交给 FAQ 或 Order；两位专员都能回到 Triage。FAQ 与 Order 没有直接相互交接的配置 |
| 04 本地工具 | `lookup_faq(query)`；`query_order(order_id)` | Runner 执行相应 Python 工具，分别查询政策与订单，返回结构化状态和事实，不是前端按钮或另一个模型 |
| 05 业务数据 | `policies.json`；`orders.json` | 政策 RET-001；订单 A1001/A1002/A1003。工具通过 `faq_data.py`、`order_data.py` 中的数据源接口读取，可替换数据来源 |
| 06 答复与返回 | 工具结果回传 Runner，再请求模型组织回答；显示答复与实际事件 | `session.py` 保存结果历史与 `last_agent`，页面返回后等待下一条用户输入；连续会话从当前 Agent 接续，不强制每轮重新从 Triage 开始 |

## 一次问题怎样运行

新会话从 Triage 开始。用户发送“我的订单 A1001 到哪了？”后，Triage 通过配置的 handoff 交给 Order；Order 请求 `query_order(order_id="A1001")`，Runner 执行工具。工具读取 `orders.json`，返回蓝牙耳机、已发货、模拟物流和 MOCK1001。Runner 把工具结果带回模型，Order 据此形成答复，页面显示答复及实际事件。

简单路径可能产生三次模型请求：Triage 选择交接、Order 选择查询工具、Order 根据工具结果回答。执行 Python 工具本身不是一次模型请求；Agent 个数不决定请求次数，实际次数以运行记录为准。

如果缺订单号，Order 先追问并结束本轮。下一条输入“A1002”与已有历史一起处理，查询台灯、待发货、暂无物流。每次订单查询应调用当前工具，不把旧结果当作新查询。

政策转订单的已验证路径是：**FAQ → Triage → Order → query_order**。这属于内部任务转交，不代表接通真人客服。新会话重建历史和当前 Agent，重新从 Triage 开始；刷新页面也会产生新页面会话，没有跨设备或重启恢复聊天能力。

## 右侧支撑栏

- **DeepSeek API**：远端模型服务，当前配置为 `deepseek-flash`；多个角色使用不同职责与工具配置，共用同一模型配置。Runner 请求模型，模型返回交接、工具调用或答复；模型不能直接读取本地 JSON。
- **运行与配置**：Python + 项目 venv，依赖版本、服务地址、模型配置和服务端密钥。当前本机启动时在终端隐藏输入密钥；尚未改为云端平台 Secrets 启动。
- **事件与证据**：RunHooks 记录实际交接、工具参数和结果，结合请求/会话标识、usage、耗时和源版本形成记录。页面展示实际事件，不展示私有推理；图中不表示事件一定实时流式出现。证据文件不等于恢复聊天的持久化存储。
- **业务边界**：只读模拟订单与政策；退货申请需人工审核，不保证获批；没有退款执行、真实工单、真人接入或真实商家接口。订单没有签收日期与预计送达时间，不能据已发货推算。

## 状态与验证

订单工具区分 `ok / invalid_input / not_found / unavailable`；政策工具区分 `ok / no_match / unavailable`。查无记录、未收录政策和请求运行失败是不同结果。缺少信息不能编造，工具不可用不能用旧记录冒充当前结果。

当前实际成果：订单与政策查询、多轮补充、角色交接、新会话重建、页面会话隔离、实际执行事件已实现。后台冻结版本 `4f49d09` 开发集 15/15、留出第 2 轮重测 10/10；首轮保存异常中断记录保留。最新版机页面关键复查 5/5，是本机关键流程检查，不表示新版云端已验收。固定样本划分公开可见，不作为外部盲评或总体准确率承诺。

## 后续 UI 怎样使用这张图

建议后续页面把“体验客服”和“架构总览”作为容易找到的两个入口：体验页聚焦聊天，实际执行事件可展开查看；架构页展示图片和这份文字说明。SVG 适合网页缩放，PNG 适合简历附件、演示文稿和截图展示。栏目尚未接入，需交界面设计与开发实现对话确认落地。

公网部署是今晚新增目标，尚未完成；模拟工单 `create_mock_ticket` 是后续可选扩展，未实现。商品浏览、购物车、支付、库存和履约等完整电商交易链路不属于当前范围。
