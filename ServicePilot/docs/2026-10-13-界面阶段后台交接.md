## 当前可复用的 Python 接口

`servicepilot/session.py` 的 OrderSession 已同时管理 Triage、FAQ、Order；名称沿用前阶段。创建 OrderSession(config)，调用 await session.ask(question) 得到单轮 dict。RunConfig 继续使用既有 DeepSeek Chat Completions 和设置；不要从前端传入或暴露密钥。

实际返回字段：input、starting_agent、status、events、started_at、finished_at、elapsed_seconds；完成时还有 final_answer、final_agent 和 usage；运行异常时有 error_type、http_status。status=completed 表示本轮完成，可能包含 no_match/not_found/unavailable 的业务答复，不等于查到资料或订单。只有真实运行异常是 status=failed。

events 已有实际 model_request、handoff、tool_call、tool_result。handoff 含 source_agent/target_agent；工具事件含 tool、call_id、arguments 或 result。lookup_faq 输入 query，成功含 source=local_mock 和 policy（policy_id/category/title/content）；query_order 输入 order_id，成功含 order。只展示公开事件和结果，不展示私有推理。

新会话/重置应创建新的 OrderSession，不能仅清空界面消息而保留旧 items 或 current_agent。不同会话不能共享一个 OrderSession。当前没有 HTTP 路由、会话服务或 Web 前端；下一阶段需要实现最小适配层并实际验证隔离与重置，不把本段设计当已实现接口。
