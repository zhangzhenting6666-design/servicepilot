## 1. 今晚实现范围与顺序

先完成浅色主题、顶栏、三个横向栏目、聊天与真实事件的布局，然后接入架构SVG和项目介绍；复查关键交互后推进云端运行和实际网址。沿用 Streamlit 1.65.0、PageConversation、OrderSession 与已有查询工具。不开发流式输出、新业务工具、订单后台、退款、工单、登录或新前端框架。

常规细节按本稿直接实施。Streamlit 原生聊天消息保持上下布局，允许用户消息不完全右对齐；输入保留原生发送图标。这两项优先保证可操作性。事件详情默认折叠，桌面辅助栏显示本轮简要结果；窄屏辅助栏落到聊天之后。无需另做移动端业务组件或引入屏幕宽度检测服务。

阶段定义：设计稿、文案、映射和提示词已完成；它们不代表新界面已接入或案例已通过。本次没有运行产品或调用模型。

## 2. 样式规则（取自首版浅色分支）

| Token | 值 | 用途 |
| --- | --- | --- |

| text | `#17332D` | 主标题、正文、关键事实 |
| secondary-text | `#65796F` | 帮助说明、字段名、注释 |
| border | `#DFE7E2` | 1px 卡片与分隔线 |
| soft | `#E9F1EC` | 标签、客服头像背景 |

| user-surface | `#E7EFE9` | 用户消息背景 |
| warning-bg / text | `#FFF7E6` / `#805A16` | 暂不可用、提醒 |

| disabled-bg / text | `#EDF1EE` / `#65796F` | 禁用输入与按钮，配合原生 disabled |

保持白与浅灰绿的大面积占比；不加深色执行面板、黄绿强调、竖向菜单、渐变或强阴影。品牌S标记36×36px，圆角11px；移动32×32px。系统字体 `Microsoft YaHei, PingFang SC, Segoe UI, sans-serif`，不下载字体。主要文字使用16px/1.65；桌面主标题28px/1.35、600；手机24px/1.4；小标题18px/1.5、600；辅助文字14px/1.6，说明最小13px。禁用标签仍可读。

桌面内容宽度上限1200px，居中；水平留白28px，品牌区上下22px，导航高56px。正文顶部32px，区块之间24px，卡片内24px，双栏间20px。聊天:事件约为 2.7:1，事件栏目标280–320px。卡片12px圆角、按钮8px、订单事实卡9px。主按钮背景深绿，次按钮白底细边；hover 用 `#145B48`，focus 保留原生可见焦点，补充深绿2px环时不去掉默认焦点。触摸目标至少44px。

Streamlit theme 建议：`base="light"`，`primaryColor="#196E57"`，`backgroundColor="#F5F7F6"`，`secondaryBackgroundColor="#E9F1EC"`，`textColor="#17332D"`。白卡片使用带 key 的容器局部 CSS，不靠主题 secondaryBackgroundColor 把所有组件强行涂白。确认启动工作目录能发现 `.streamlit/config.toml`，不得凭文件存在认定主题已加载。

## 3. 三个栏目

### 顶部品牌与横向导航

品牌为 ServicePilot，副标题“模拟电商售后 · Agent 工作流”。正式运行页面右侧标签“模拟业务 Demo”；设计稿为“设计预览 · 预设样例”。标签不是服务健康指示灯，不能预先写“已连接”或“已上线”。导航准确为“客服体验 / 架构总览 / 项目介绍”，顺序固定，选中深绿文字与2px下划线。栏目切换只改变内容可见性，保留当前客服会话，不调用查询工具、不自动开新会话。

### 客服体验

栏目眉题“客服体验”；主标题建议“让订单与规则查询有依据。”；说明“查询演示订单，或了解模拟退货申请规则。”。沿首版保持标题位置和层次，收敛原“每一次回答，都有查询依据”的绝对表述，因为追问或请求失败并不一定调用查询工具。标题右侧“新会话”是次按钮。

主体：左侧白色聊天卡片、右侧白色执行记录卡片。聊天从空会话开始，不默认灌入 A1001 样例回复。空提示“今天想了解什么？”及两条示例按钮“查一下 A1001 / 了解退货规则”。按钮只填入草稿，说明“点击填入，发送后执行查询”；不点击即消耗 API。处理完成后保留示例入口，按钮在 busy 时禁用。

消息使用原生 `st.chat_message`，客服身份统一“售后助手”；只有实际公开事件足以确认本轮响应角色时才显示订单/政策角色。实际 `final_answer` 原样用 Markdown 展示，不强行重写模型答复。订单/政策事实卡是附加展示，只读本轮 `tool_result` 的成功结果；字段缺失不补值，答复失败时不能拿旧成功结果展示为本轮成功。

订单卡展示订单号、商品、订单状态、承运商、模拟运单；待发货无物流显示“暂无物流信息”，已取消保留工具返回状态，不装饰为异常。政策卡显示工具实际政策编号和正文；仅不依赖工具的提醒可由页面固定显示。多个成功结果分工具展示，不把数组最后一条假定为用户全部问题的唯一结果。

输入在聊天卡片底部、页面正常文流中；不做固定底栏或独立高聊天滚动区，避免手机软键盘覆盖。输入文本16px，建议 placeholder“输入订单或售后问题…”，下方常驻“模拟订单与政策 · 不直接执行退款”。保留 Enter/Shift+Enter 的原生行为、2000字符上限与组合态人工检查。

### 架构总览

眉题“架构总览”；标题“从用户提问，到有依据的回答。”。下方一句“页面管理交互，会话保留上下文，Runner 串联模型与本地工具。”，完整 SVG 自适应预览。使用已有文件，保留其图例、支撑栏和边界，不重绘精简链路。

图上方有“放大查看完整图”，下方有“下载 SVG”。推荐 native expander 包含约1680px宽的完整SVG与局部横向滚动容器；只在图形容器内滚动，页面不横向溢出。默认预览是全图鸟瞰，不能认为缩到手机后仍能读每个标签。SVG 文本替代说明：“界面 → 会话 → Runner → Triage/FAQ/Order → Python工具 → 模拟JSON → 工具结果 → 答复；模型请求、事件记录与业务边界为支撑部分。”

再给三条短说明：模型提出交接/查询，Runner 执行；JSON 是本地模拟事实；公开事件完成后展示，内部交接不代表接通真人。原SVG包含制作时进度文字，部署后若状态变化，由开发同步对应的状态说明并记录，不能用旧图进度当作新云端验收。

### 项目介绍

沿 about.png 保留首屏结构：眉题 → 标题“让售后助手的行为可检查。” → 简介 → 两列能力与边界。2026-10-14主线按用户最新意见扩充图文内容，具体文案与素材见[项目介绍图文内容与开发接续](2026-10-14-项目介绍图文内容与开发接续.md)。这项内容补充覆盖此前“只保留两列”的限制，不改变浅色风格和三个栏目。

简介：“基于 OpenAI Agents SDK 与 DeepSeek，在 Codex 协助下构建的模拟售后 Demo。”

左列“可体验的能力”：订单与政策查询、多轮补充、角色交接、新会话与实际事件查看。

右列“验证与边界”：固定样本在后台冻结版本4f49d09上，开发15/15、留出第2轮重测10/10；首轮中断记录保留。模拟订单与政策，无真实退款、工单或人工接入。新界面与云端结果单独记录；不称总体准确率100%或首次盲评全部通过。

两列之后增加：三个具体场景、两张已有本机真实运行截图、四步工作方式、分版本评测与两项实际排错、三阶段时间线及本人/Codex贡献。截图明确标注历史旧界面，可放大查看；在当前设计稿中不当作新版UI或云端运行证据。实现中沿用原型的图文顺序与浅色样式，手机单列；见`about-section.html`和`about-content.css`。

原型已提供完整架构入口；正式应用优先切换到内部“架构总览”，不依赖本机静态预览网址。评测有公开记录才提供外部报告链接，否则在应用内显示摘要。已有评测数字来自共享文档，本次未重新执行。

## 4. 390px窄屏规则

断点：≥960px双栏；<960px聊天与执行区按顺序堆叠；≤600px紧凑字号与间距。不检测用户设备，不另存屏幕宽度到后台。

390px视口两侧各16px，内容宽358px；卡片内16px，正文可用326px。品牌区上下16px，副标题13px；右侧标签可换行但不挤压品牌。导航三个标签均为四个汉字，14px，每项约104px，仍保持一行；间隙12px，44–48px高，不能变汉堡菜单或竖向列表。主标题24px允许两行，“新会话”放标题说明下方独立操作行并靠右，不与长标题争宽。

顺序：品牌 → 横向导航 → 标题/说明 → 新会话 → 模拟业务提示 → 聊天/输入 → 执行记录 → 页脚。卡片随内容增高，不设固定viewport高度。消息最大宽100%，长运单/JSON `overflow-wrap:anywhere`；事实字段长值换行，标签不超过字段行的40%。示例按钮可换行，输入不横向撑开。

执行记录标题带最近轮次结果摘要；“查看本轮实际执行记录”默认折叠。此折叠策略桌面也采用，统一原生组件行为；桌面摘要常见，展开查看事件。完整JSON再折叠一层。原生 expander 状态不靠 CSS 在不同断点强行切换。

项目介绍两列在≤600px依次变为“可体验的能力 / 验证与边界”，间距24px。架构全图预览宽358px，随后保留放大入口和文字说明；放大图在专用容器内可横向滚动，其他内容无横向滚动。检查390×844，并额外看320px与桌面1440px。

## 5. 状态与操作反馈

| 状态/触发 | 聊天与操作 | 执行记录 |
| --- | --- | --- |
| 空会话 | 两条示例只填入；输入可用，新会话可用 | “发送问题后，这里显示实际执行记录。” |
| 空白发送 | 不新增消息；“请输入问题” | 不生成事件 |
| 订单/政策完成 | 展示实际final_answer；符合条件的本轮事实卡 | 按本轮返回事件原顺序，显示真实工具状态 |
| 缺编号追问 | 原样显示追问，下一输入留在同会话 | 没有调用就不造工具事件 |
| 格式错误 | 提示有效格式；允许用户补充 | 仅实际返回时显示invalid_input |
| running/busy | 原用户输入保留；“正在处理，完成后展示答复和实际事件…”；禁用输入、示例、新会话、重试 | “处理中，完成后展示实际事件”；不播Triage/查询动画，不倒计时 |
| not_found | 明确未找到，提示核对编号；不提供失败请求重试按钮 | “未找到订单”；与工具不可用分开 |
| no_match | 模拟政策未收录，建议人工确认；不编规则 | “政策未收录” |
| unavailable | 工具不可用；模型实际解释保持；可稍后重新提问 | “工具暂不可用”；不引用旧事实 |
| 请求failed | “本次未能取得回复，请稍后重试。”；提供“重试此问题” | 只显示实际可用事件；异常类型/短请求标识可折叠 |
| EmptyResponse | “未收到可展示的回复，请重试。”；恢复输入 | 标为请求失败，不做空白成功气泡 |
| completed无事件 | 正常回复 | “本次未提供执行事件”；不能推断没有工具调用 |
| 新会话有历史 | 内联确认：“当前聊天将从页面清除，后台上下文也会重建；已有运行记录仍保留。”；“开始新会话 / 取消” | 确认成功后清空本页事件；取消保留 |
| 新会话失败 | 提示失败，保留当前历史；不能toast成功 | 保留旧事件 |
| busy期间重置尝试 | 原生disabled；后台保护也保留 | 不称已取消后台请求 |
| 退款/规则外请求 | 仅实际答复与人工处理建议；没有退款、转人工或工单成功页 | 内部交接与真人接入区分 |
| 后台未配置/初始化失败 | 显示“客服暂不可用”；不在公网要求访客终端输密钥；聊天禁用，另两栏目仍可读 | 无事件；不伪装运行成功 |
| 云端限额/繁忙（若开发接入） | 只在确有状态时显示“当前演示繁忙，请稍后再试”或“本次演示额度已用完” | 不把网断/未知异常自动分类为额度耗尽 |

同一问题重试使用现有 `c.submit(..., retry=True)`，产生新请求标识，保留此前失败轮次。不增加自动重试、取消后台、处理中编辑草稿或流式答复。正式页面不把设计稿里的状态选择器带到线上。

## 6. Streamlit组件与现有数据映射

| 设计组件 | 实现推荐 | 现有来源/注意点 |
| --- | --- | --- |
| 品牌/常驻模拟提示 | 静态HTML或st.markdown/st.caption | 仅可信静态内容允许HTML；用户消息/事件动态文本必须转义或原生渲染 |
| 横向导航 | st.tabs，默认客服体验，默认on_change="ignore" | 切换不触发查询；不可将会话初始化放入会被频繁重建的位置 |
| 白色工作区 | st.container(border=True,key=...) + st.columns([2.7,1]) | 局部.st-key-* CSS；窄屏检查实际列堆叠 |
| 用户/客服消息 | st.chat_message + st.markdown | c.turns中的input/final_answer/status；保留原生布局 |
| 订单/政策事实卡 | 本轮tool_result → 原生文字或转义后的定义列表 | status=ok；只显示已有字段，不解析自然语言补事实 |
| 示例草稿 | 两个st.button，回调写chat_<session_id> | 在输入组件实例化前写入；点击不调用c.submit |
| 输入 | 嵌入聊天容器的st.chat_input | 保留key="chat_"+c.session_id、on_submit、owner、max_chars=2000、disabled=c.busy |
| 新会话/确认 | 现有st.button和confirm_reset内联容器 | 原c.reset、失败保留；busy时禁用 |
| 等待 | 现有st.fragment轮询 + st.spinner | 保留collect→rerun与0.5秒轮询；不加入另一套pending状态 |
| 请求重试 | 现有st.button | 保留unique request_id与retry=True，busy禁用 |
| 执行记录摘要/详情 | st.caption + st.expander + st.json | c.turns[n].events；handoff/tool_call/tool_result，不推测模型私有推理 |
| 架构预览 | st.image读已有SVG，或可信SVG用st.html嵌入 | 路径按app.py位置解析，云端文件必须打包 |
| 架构放大/下载 | st.expander内局部可滚动SVG；st.download_button | 不依赖本机file://，也不要求新增公网静态文件API |
| 项目介绍图文 | st.markdown + st.columns + st.image + st.expander | 新增图文内容说明、两张历史真实截图；版本/重测/贡献限定保留，不整页嵌入预设HTML |
| 后台未就绪 | 先渲染shell/静态栏目，再在客服区展示不可用状态 | 当前app.py早期st.stop会阻断新静态栏目，开发调整显示顺序，不重写Agent逻辑 |

官方参考：[tabs](https://docs.streamlit.io/develop/api-reference/layout/st.tabs)、[chat_input](https://docs.streamlit.io/develop/api-reference/chat/st.chat_input)、[container](https://docs.streamlit.io/develop/api-reference/layout/st.container)、[主题](https://docs.streamlit.io/develop/concepts/configuration/theming)。已核对1.65.0页面文档；容器key可作为局部CSS类，嵌套聊天输入是inline，原生tabs默认计算所有页内容。显示性渲染与后台请求必须分开，隐藏栏目不能发请求。

动态CSS只用于视觉与响应式，保留按钮语义、键盘焦点和disabled。避免生成的hash类、nth-child全局选取、iframe自制输入或父页面DOM注入。Streamlit列断点可能不等于本稿960px，开发以实际DOM做有作用域的列堆叠规则；不能全局把所有横向块改列，避免新会话确认与导航被破坏。
