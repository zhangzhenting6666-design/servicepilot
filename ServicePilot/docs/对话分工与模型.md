## 对话怎么分

| 建议名称 | 使用时机 | 负责什么 | 修改范围 |
| --- | --- | --- | --- |
| 01｜项目主线与验收 | 长期保留，每个里程碑回到这里 | 产品目标、优先级、阶段推进、原理解释、验收与作品集 | PRD、推进路线、任务看板；默认不改代码 |
| 02｜开发实现 | 长期保留，一次完成一个功能 | 读代码、实现、常规报错、必要验证、结果交接 | 当前任务需要的业务代码、运行入口、测试；不改 SDK 库内部实现 |
| 03｜专项排障－问题名 | 同一问题经过两次有证据的修复仍失败，或排查持续较久而范围未缩小 | 复现、定位、最小修复与恢复方法 | 默认先分析；需要改代码时暂停开发对话，由排障对话接手该问题 |
| 04｜界面设计 | 后期需要明确页面与交互时开启 | 聊天、重置、模拟提示、事件展示的线框、文案与交互 | 原型、设计说明；界面代码由开发对话实现，或明确交接给这个对话 |

先使用 01 和 02。03 每次围绕一个具体问题，完成后归档或结束；04 到界面阶段再开。小报错直接在 02 处理，不为每条红字新建聊天。

## 哪些内容放在哪里

- PRD.md：最终产品目标、范围、业务规则和验收要求。
- 从示例到产品的推进路线.md：阶段顺序与进入下一阶段的条件。
- 任务看板.md：已完成、证据、当前唯一任务、阻塞、下一步和关键决策。
- 排障记录（按需）：失败命令、错误、已尝试办法、根因、修复文件和验证结果。看板只保留结论与记录位置。
- 界面说明（后期）：页面、交互、加载/错误/空状态、与后台的接口约定。

这些项目文件用于交接，不依赖其他对话自动知道聊天历史。每个新对话先读 开始这里.md 和任务看板，再按当前任务读相关文档。无需复制全部聊天记录或整个仓库。

## 修改代码的边界

同一个目录里的聊天可以修改同一份文件；拆聊天本身不隔离代码。同一时间只安排一个对话修改代码。专项排障接手时，开发对话暂停写入，完成后交还。

2026-10-13：航空入口仍依赖下载仓库的航空示例，已在工作区建立本地 Git 并保存最小完整航空基线；当前分支 feature/order-query。电商入口使用 ServicePilot 内的独立业务模块，仍复用同一个已验证虚拟环境。基线、启动与恢复方式见[基线与启动说明](基线与启动说明.md)。若以后并行改界面与后端，应使用独立 Git worktree（独立工作目录）；只建两个聊天或在同一目录切换分支，不构成文件隔离。

电商改造复用现有示例，修改业务 Agent、指令和工具；现有航空版本作为学习基线保留。不要修改 .venv/Lib/site-packages 中的已安装库，也不要为增加订单功能改写 SDK 的 src/agents 内部实现。当前示例已经做过 DeepSeek 兼容适配，不能称为完全未修改的官方原版。

## 开工与收工

开工：确认当前阶段、任务编号、目标、允许修改的文件、验收条件和前一个任务留下的阻塞。

收工：写回完成情况、实际证据、修改文件、失败项、下一步。每个可验收的小功能或排障结论都记录一次，不等几十轮对话后再总结。改变产品范围必须写回 PRD 或看板的决策记录。

如果对话已混入多个不相关任务、不断重复旧错误、或进入新的独立里程碑，就带交接卡开新对话；不按固定消息条数机械切换。只切换模型不能替代项目记录。

交接卡（任何对话结束任务时填写）：

```text
任务编号与目标：
当前代码版本/分支（没有则写尚未建立）：
已完成与修改文件：
实际运行命令与证据位置：
未完成、失败、已尝试的办法：
关键决策与原因：
下一步及验收标准：
```


## 模型与额度

先选对话职责，再按任务难度选择当前客户端可用的模型。明确的小改动用日常模型，复杂定位再升级；不要把长上下文或缺交接记录的问题全归因于模型强弱。

开发助手的订阅额度与产品运行时的 DeepSeek API 费用分别记录。调试先做对应的小范围检查，记录实际调用；航空演示的调用次数不等于电商产品的效果评测。

参考：[OpenAI 官方长期任务实践](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex)，建议把状态与完成条件留在项目文件里。
