## 一分钟口头介绍

> 我做的是 ServicePilot，一个模拟电商售后 Agent Demo。我想展示用户用自然语言查询订单和退货规则时，系统如何补齐信息、调用工具，并让回答依据可检查。
>
> 用户的问题由 Triage 分流给订单或政策客服。缺订单号会先追问，补充编号后继续查询；政策问题切换到订单时会发生内部角色交接。界面还展示实际工具参数和查询结果，方便核对答案依据。
>
> 我关注的产品决策包括：缺信息先追问、查无记录与工具故障分开反馈、没有依据不编到货时间，以及不把内部交接显示为接通人工。我参与需求审阅、范围和验收确认、体验反馈，代码实现与验证借助 Codex 完成。
>
> 目前应用已公开部署。固定样本最终开发15/15、留出第二轮重测10/10，云端关键场景另验5/5；它使用模拟数据，还没有真实退款、人工通道或生产规模验证。

## 四个常见追问

**为什么分三个 Agent？** Triage 负责识别需求，FAQ 负责政策，Order 负责订单查询，各自配置职责和可用工具。这样容易展示和核对边界。项目没有做单 Agent 对照实验，不能声称多 Agent 已被证明效果更好。

**模型怎样拿到订单事实？** 模型提出 query_order 调用并给出订单号；Runner 执行 Python 工具，读取模拟 JSON，工具返回事实，模型据此组织回答。模型没有直接连接真实电商平台。

**查不到怎么办？** 编号格式错误提示更正；编号有效但无记录提示未找到；数据源不可用提示查询暂时失败。可以建议联系人工，但 Demo 没有创建工单或接通人工。

**你做了什么，AI 做了什么？** 本人已确认的参与见[个人贡献说明](个人贡献说明.md)：需求审阅、范围/验收确认、真实运行配合、页面反馈及流程学习。技术实现、排错和验证由 Codex 协助完成。本人独立手写或调试的具体部分，须按实际经历补充。
